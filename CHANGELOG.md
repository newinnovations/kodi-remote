# Changelog

All notable changes to this project are documented in this file.

## 2026-08-16

Addressed issues from REVIEW-1.md:

- **Serialize polling and hotkey commands (Issue 1, High).** Added a `SemaphoreSlim`-based `RunExclusiveAsync` helper in `MainWindow.xaml.cs` so the poll timer, the initial fetch, and hotkey-driven commands never run concurrently. Scheduled polls are skipped (not queued) while a previous operation is still in flight; hotkey presses wait their turn instead. `KodiClient` now assigns a monotonically increasing JSON-RPC `id` to every request instead of always using `id = 1`.
- **Distinguish connection failures from "nothing playing" (Issue 2, High).** Introduced `KodiResponse` (`KodiClient.cs`) which reports success, a JSON-RPC error, or a transport/connection failure instead of silently returning `default`. `SendRequestAsync`/`SendBatchAsync` now check `EnsureSuccessStatusCode`-equivalent status and surface non-2xx responses and JSON-RPC `error` payloads as failures. `MainWindow.FetchKodiStatusAsync` and the command helpers (`AdjustZoomAsync`, `SetSubtitleAsync`, `ToggleSubtitleAsync`) now check a `PlayerLookupStatus` (`Found` / `NonePlaying` / `ConnectionError`) and preserve the last-known display, showing a distinct "Connection error - showing last known state" status instead of clearing to "Nothing playing".
- **Harden JSON parsing and fire-and-forget error handling (Issue 4, High).** Replaced direct `GetProperty`/`GetInt32`/`GetDouble`/`GetBoolean` calls with defensive `TryGetInt32`/`TryGetDouble`/`TryGetBool`/`TryGetString`/`TryGetObject`/`TryGetArray` helpers in `MainWindow.xaml.cs` that validate presence and JSON kind before reading. Malformed subtitle entries are now skipped with a log line rather than throwing. `RunExclusiveAsync` wraps every poll-timer tick and hotkey dispatch in a try/catch that logs the failure and keeps the polling loop alive instead of producing an unobserved task exception.
- **Extract a Kodi protocol client from the UI (Issue 5, Medium, partial).** Added `KodiClient.cs`, which owns the `HttpClient`, JSON-RPC envelope, batching, and connection-reachability logging that previously lived inline in `MainWindow`. `MainWindow` now calls typed client methods instead of building requests itself. `SubtitleTrackItem` now implements `INotifyPropertyChanged` so its `Text`/`IsSelected` properties support change notification. A full MVVM split (dedicated view model, further service decomposition) is not included in this change.
- **Validate hotkey registration results (Issue 6, Medium).** `RegisterHotKey` return values are now checked; failures log the Win32 error code (`Marshal.GetLastWin32Error()`) and a description of the affected binding. Only hotkeys that registered successfully are tracked and unregistered on shutdown, and the startup log reflects the actual number of bindings that succeeded instead of an unconditional success message.
- **Cancel outstanding work and release resources on shutdown (Issue 7, Medium).** Added a window-lifetime `CancellationTokenSource` that is passed to every Kodi request and canceled in `OnClosed`, before the timer is stopped and hotkeys are unregistered. `KodiClient` (and its `HttpClient`) is disposed on close, and the `HttpClient` now has a 10-second timeout instead of none.
- **Improve settings load/save diagnostics (Issue 8, Medium).** `KodiSettings.Load` now catches only the expected `IOException`/`UnauthorizedAccessException`/`JsonException` types (instead of all exceptions), logs the specific failure, and renames an unreadable/corrupt `settings.json` to a timestamped `.bak` file for diagnosis instead of silently overwriting it. Failure to save default settings (e.g. an unwritable directory) is now logged explicitly and the app continues with in-memory defaults rather than letting the exception propagate from the constructor path.
- **Reduce chatty status refreshes (Issue 11, Low).** Added `KodiClient.SendBatchAsync`, which sends multiple JSON-RPC requests in a single HTTP round-trip (standard JSON-RPC batching) and returns the responses in request order. `FetchKodiStatusAsync` now combines `Player.GetProperties`, `Player.GetItem`, and `Player.GetViewMode` into one batched HTTP call, reducing the poll path from four sequential requests to two (active-player lookup, then one batch).

Not addressed (explicitly out of scope)

- **Issue 3** (plaintext credential storage, insecure default URL) — left as-is; the application is intended for local/trusted-network use only.
- **Issue 9** (no automated tests/CI) — left as-is; the project is tested manually and the existing `release.ps1` is considered sufficient for its intended use.
- **Issue 10** (layout/accessibility on varied displays) — left as-is; the application targets specific fixed hardware and is not intended for general accessibility.
